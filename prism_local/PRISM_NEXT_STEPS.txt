STEP 8 - MULTI-ACCOUNT / MULTI-PAGE DATA MODEL (design BEFORE wiring
real publishing - confirmed the current schema does NOT support this
yet, only a bare `platform` string)
------------------------------------------
Goal: a user must be able to (a) connect MULTIPLE pages/accounts on
the SAME platform (e.g. two Facebook Pages, two Instagram Business
accounts) and (b) connect multiple DIFFERENT platforms, then choose
exactly which connected page/account any given post/scheduled item
goes out on.

[ ] Add a `social_accounts` table:
      id, owner, platform, account_id (the platform's own page/
      account ID), account_name (display label, e.g. "Prism Main
      Page" vs "Prism Second Shop"), access_token, refresh_token,
      token_expires_at, is_default, created_at
    One row per connected page/account - a single user can have many
    rows per platform.
[ ] Add `social_account_id` (FK into social_accounts) to
    `scheduled_posts`, so a post targets a specific connected page/
    account, not just a platform name. Keep the existing `platform`
    column too (denormalized, still useful for analytics filters).
[ ] Build a "Connected Accounts" settings screen: list every
    connected page/account grouped by platform, a "Connect another
    page" action per platform, and a way to mark one as default.
[ ] Schedule Queue's create/edit UI needs an account picker (not just
    today's platform picker) whenever a user has 2+ accounts
    connected on the same platform.
[ ] Meta note: a Facebook Login for Business token can grant access
    to multiple Pages the user manages, and each Page can have at
    most one linked Instagram Business account - fetch and store ALL
    of them via /me/accounts at connect-time (not just the first),
    so multi-page selection works immediately once review is done.
[ ] TikTok note: the Content Posting API issues one access token per
    single creator account per OAuth flow - supporting multiple
    TikTok accounts means running the connect flow once per account
