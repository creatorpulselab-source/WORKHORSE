OVERVIEW
--------
Prism is a full-stack SFW (safe-for-work) AI-powered social media
content generation studio. Upload one image or video and instantly
generate platform-optimized captions, AI image prompts, video prompts,
pose series, X threads, and hashtag sets — all tailored to your content
type, platform, brand voice, and style.

Built on FastAPI + Uvicorn (Python), deployed to Fly.io with persistent
SQLite storage. Supports multiple AI providers with Gemini 2.5 Flash as
the primary cloud provider.

PERFORMANCE OPTIMIZATIONS
================================================================

Context Caching (Generate All mode with Ollama):
  - One vision call generates a comprehensive image description
  - Cached in memory (10-minute TTL, per image hash)
  - All subsequent modes (caption, flux, WAN, poses) use
    description instead of re-sending the image
  - Threading deduplication: if prefetch is running when Generate
    fires, Generate waits for prefetch result (no double API calls)
  - Cloud providers (Gemini): run all modes in parallel instead
    (parallel threads, results appear as they complete)

Background Pre-fetch:
  - Immediately after image upload, /api/prefetch fires
  - Pre-computes description while user configures settings
  - By the time user clicks Generate All, cache is warm

Image Resizing:
  - All images resized to max 854×480 before AI calls
  - Matches video pipeline resolution
  - Dramatically reduces vision token count (20× reduction
    from 4K images), speeds up processing

Streaming:
  - Gemini: true token-by-token streaming via generate_content_stream
  - All Generate All modes fire in parallel threads
  - Results pop in as each mode completes (fastest first)
  - Ollama: sequential streaming with token-by-token display

================================================================
VIDEO PROCESSING PIPELINE
================================================================

Upload: Same drop zone, drag-drop MP4/MOV/WEBM up to 500MB

Gemini Provider (Primary):
  - Video uploaded to Gemini Files API
  - Gemini watches the full video natively (motion, audio, dialogue)
  - No frame extraction needed
  - Generates captions/prompts from complete video understanding

Ollama / Fallback Pipeline:
  1. Take-5-Skip-10 motion detection — extracts up to 30 key frames
     at 480p (854×480) using scene change detection
  2. Hold-and-Wait batching — groups 3 frames into side-by-side
     grid image, sends each batch to AI for description
  3. Audio extraction via ffmpeg (16kHz mono WAV)
  4. Whisper transcription — faster-whisper (local, tiny model)
     OR OpenAI Whisper API fallback
  5. Synthesis — combines visual analysis + audio transcript
     into caption/prompt

🎤 Audio transcript toggle: ON by default, shows when video loaded

DISTRIBUTION & TARGETING ENGINE
================================================================

Purpose: closes the loop from "what to post" to "where to get it

hub discovery is search-assisted only (client-side, opens Google/

manually submits the data — Prism never scrapes or queries
Instagram/TikTok servers directly.

  - Curated, user/admin-submitted database of feature-page /
    shoutout accounts (hubs table)
  - Per hub: platform (instagram/tiktok), handle, niche, tier
    (Micro <25k · Mid-Tier 25k-250k · Mega 250k+), bio snippet,
    submission rule, required hashtags
  - Niche-matched search + tier + platform filters
  - "Search Google" / "Search In-App" buttons build a query and
    open it in a new tab for manual discovery
  - Selecting a hub's required hashtags auto-appends them to the
    caption at generation time (hub_hashtags)

Reddit Research Panel:
  - Static curated dataset (12 niche categories) of relevant
    subreddits with description + posting norms
  - No live Reddit API calls — pure reference/research aid

Targeting Vault:
  - Save the current hub + hashtag selection as a named, reusable
    vault (per-user, vaults table — stores a full snapshot so it
    still works even if a hub is later edited/removed)
  - "Load This Vault" instantly restores the selection for repeat
    campaigns/niches without re-searching

Pre-Publish Checklist:
  - 📋 button on generated post captions and in the Distribution
    modal
  - Ephemeral reminder checklist: hashtag inclusion + per-hub
    submission-rule reminders — resets each time it's opened,
    nothing persisted server-side

Crowdsourced Health Reporting:
  - 🚩 Report button on each hub (reasons: inactive, not accepting
    submissions, spam/fake, other + optional note)
  - One report per user per hub (duplicates rejected)
  - After 3 distinct reporters, the hub auto-flags (status
    'flagged') with a visible warning badge — stays visible for

New DB tables: hubs, hub_reports, vaults (SQLite, same DB file as

PUSH NOTIFICATIONS (Web Push / VAPID)
================================================================

Opt-in browser push notifications (Preferences → 🔔 Notifications),
built on the standard Web Push API + a VAPID keypair generated once
and persisted server-side (vapid_private_key.pem / vapid_public_key.txt).
A background daemon thread (_notification_worker) checks every 15
minutes per subscribed user; each notification type self-throttles so
it fires at most once per its own natural cadence, and every send is
logged in a notification_log table (owner, kind, ref, sent_at) to
guarantee no duplicate pushes for the same event.

Nine notification types, each individually toggleable:
  🔥 Streak at risk        — haven't generated today, fires 8pm if
                              yesterday was active and today isn't yet
  📅 Scheduled post due     — a pending Schedule Queue item's time arrived
  ✨ Daily limit reset      — admin-set daily generation limit rolled
                              over at midnight after being hit
  👋 Inactivity nudge       — 3+ days with no generations, re-nudges
                              at most every 3 days
  🎉 Streak milestone       — celebrates hitting 7/30/100/365 consecutive
                              days on the day it's reached
  📊 Weekly recap           — Monday 9am summary of the past 7 days'
                              generation count + current streak
  🏆 New personal best      — fires the moment a logged engagement
                              metric (likes/views/comments/shares) beats
                              every previous post's value for that metric
  🎄 Holiday idea nudge     — surfaces a content idea 10-14 days before
                              an upcoming HOLIDAY_IDEAS entry
  🔥 Daily trend alert      — once/day (11am), looks up one real,
                              currently-trending topic in the user's
                              self-set "My Niche" (Preferences) via
                              Gemini's Google Search grounding; only
                              fires when the instance provider is Gemini
                              with an API key configured (grounding isn't
                              available on Ollama/local, so it silently
                              no-ops rather than guessing a stale trend)

Routes: GET /api/push/public-key, POST /api/push/subscribe,
POST /api/push/unsubscribe, POST /api/push/test

STRUCTURED JSON OUTPUT (GEMINI RELIABILITY)
================================================================

For modes that require exact formats (pose_series, thread, variants,
hashtag_set), Prism calls Gemini with:
  response_mime_type: "application/json"
  response_schema: typed schema (object with named array fields)

This guarantees valid JSON from the model — no regex parsing
or numbered-list extraction needed. Schemas:
  Pose Series: {"poses": [string x6]}
  X Thread:    {"tweets": [string x5]}
  Variants:    {"captions": [string x3]}
  Hashtag Set: {"high_reach":[...], "engagement":[...], "niche":[...]}

Implemented in _gemini_structured(). For Ollama/other providers,
numbered [1]...[6] parsing is still used as fallback.

================================================================
AI PROVIDER TIMEOUT PROTECTION
================================================================

GEMINI_TIMEOUT_S = 30 (30 seconds per call)
GEMINI_TIMEOUT_MS = 30000

Every Gemini call sets request_options={"timeout": 30} (genai SDK)
or http_options=HttpOptions(timeout=30000) (genai client).

Prevents cloud-overload / slow provider from leaving the Generate
button spinning silently with no error for minutes. On timeout,
the existing HTTP error handling kicks in and surfaces a message
to the UI immediately.

================================================================
VIDEO PIPELINE — ALGORITHM DETAILS
================================================================

Take-5-Skip-10 Motion Scoring:
  - Every frame resized to 854×480 via INTER_AREA
  - Gaussian blur (21×21) applied before grayscale diff
  - cv2.absdiff between consecutive frames
  - Threshold at pixel value 25 → binary mask
  - motion_score = (nonzero pixels / total pixels) × 100
  - Static threshold: motion_score < 2.5%
  - Static frames: only saved once per 30 frames
  - Motion frames: burst-capture 5, then skip 10, repeat
  - Max 30 frames extracted per video

Hold-and-Wait Grid:
  - 3 frames stitched side-by-side (each 400×225)
  - Single JPEG per batch (one AI call per 3 frames)
  - Canvas background: (20, 20, 20) dark fill
  - JPEG quality: 82

Gemini Native Video Path:
  - Video uploaded to Gemini Files API (mime_type video/mp4)
  - Polled until state == ACTIVE (3s intervals, 120s max)
  - On FAILED or timeout: file deleted, RuntimeError raised
  - Full video understanding — motion, audio, dialogue all native
  - No frame extraction or Whisper needed

Whisper Transcription (Ollama path):
  - Model: tiny, device=cpu, compute_type=int8
  - Model cache: /data/whisper_cache (Fly.io volume)
  - Lazy load: model loaded on first video processed
  - Fallback: OpenAI Whisper API (whisper-1) if OPENAI_API_KEY set

POSE SERIES — CONSISTENCY ENFORCEMENT DETAILS
================================================================

Appearance Extraction (APPEARANCE_EXTRACT_PROMPT):
  Extracts per subject: face shape + eyes + nose + lips + features,
  hair (exact shade + length + texture + style), skin tone,
  body type, EVERY visible tattoo + exact body location (or NONE),
  held items (which hand, how held), full outfit, background/setting.

POSE_CONSISTENCY_RULES (appended to every pose generation prompt):
  MUST NOT CHANGE:
    • Face, facial features, skin tone
    • ALL tattoos at EXACT same body locations
    • Held items — same item, same hand, visible to camera
    • Background + environment (exact match)
    • Outfit + accessories
  ONLY CHANGE: body pose, arm angles, head/face direction, camera
    angle/framing, weight distribution.

For Ollama/Grok providers: appearance description injected as
"SUBJECT REFERENCE — maintain this exact appearance..." prefix.
For Gemini: same prefix using Gemini's own appearance call.
Gemini image generation → Imagen 3.
OpenAI image generation → DALL-E 2 edit endpoint (image reference
padded to square PNG) → falls back to DALL-E 3 on failure.

================================================================

Per-user daily generation limit (set by admin per user):
  - Tracked in usage table (username, date, count)
  - If daily_limit > 0 and count >= limit: HTTP 429
  - limit=0 means unlimited (default)
  - Resets at midnight (date key changes)

  - 100 posts per platform per 24-hour window
  - Enforced server-side before any real platform API call
  - Prevents ever exceeding Meta's confirmed Instagram
    Content Publishing API cap (100/24h)

DATABASE TECHNICAL DETAILS
================================================================

Engine: SQLite (WAL mode)
  - PRAGMA journal_mode=WAL    — concurrent read while writing
  - PRAGMA synchronous=NORMAL  — safe + faster than FULL
  - Connection timeout: 10s on every connect()

Tables:
  history         — id, created_at, thumb, mode, platform, results,
                    posted, rating, posted_at, style
  usage           — username, date, count  (PK: username+date)
  sessions        — token, username, expires
  hubs            — feature-page/shoutout accounts database
  hub_reports     — crowdsourced hub health reports
  vaults          — saved targeting vault snapshots
  creators        — peer shoutout swap directory
  scheduled_posts — internal planning calendar queue
  post_metrics    — manually logged engagement (likes/views/comments/shares)
  push_subscriptions — Web Push subscriptions (owner, endpoint, p256dh, auth)
  notification_log   — dedup log for sent pushes (owner, kind, ref, sent_at)

Migration helper: _ensure_column(conn, table, column, type_default)
  — adds columns to existing tables without breaking old rows.

Persistent storage on Fly.io: /data volume (1GB).
  - DB_PATH → /data/history.db when /data mount is writable
  - users.json copied to /data/users.json on first boot

================================================================
WHAT-WORKED FEEDBACK LOOP — IMPLEMENTATION
================================================================

_top_performer_examples(platform, limit=2):
  - Queries history WHERE posted=1 AND rating>=4 ORDER BY
    created_at DESC LIMIT 20
  - Filters to matching platform
  - Returns up to 2 recent top-performing caption strings

These are injected into every future caption prompt as:
  "TOP-PERFORMING PAST CAPTIONS (style/structure reference,
   don't copy):\n- <example>\n- <example>"

Effect: the model learns YOUR specific style over time without
any fine-tuning — pure few-shot prompting with real high-signal
data the user already validated by posting it and rating it ≥4/5.

KEYWORD EXPANSION (IDEAS GENERATOR)

POST /api/expand-idea — accepts {keywords, prompt_type, platform, hashtags}

prompt_type routing:

  "flux_image" → EXPAND_PROMPTS_FLUX

    Each: window_days (days before holiday to surface it), 3 ideas
  SEASON_IDEAS: 4 seasons, 3 ideas each

    Travel, Fashion/OOTD, Nature, Food, Wellness, Work/Hustle,
    Friends, Home Aesthetic, Creativity)
  On This Day: /api/suggestions also returns a resurfaced past post —
    prefers a true anniversary (posted=1, rating>=4, same month/day in
    a past year), falls back to the single highest-rated eligible post
    otherwise. Tapping the card reopens that generation in the results
    view via the existing history-item loader.

BRAND VOICE INJECTION — IMPLEMENTATION

If user has brand_voice set in preferences:

  "BRAND VOICE — match this creator's tone:\n{brand_voice}\n\n"
